# Pricing feature

Pricing is server-authoritative, versioned, and stored in integer cents in `USD`.

## Flow

`POST /api/booking/quote` validates the HttpOnly booking session, server-attached booking contact, Google-resolved pickup/drop-off, and Google Routes snapshot. The browser submits booking answers but never submits a price or parameter value.

The backend then:

1. Loads one effective active version from `pricing_parameters`.
2. Calculates the service price in `pricingEngine.js` using vehicle-local time.
3. Creates a state fingerprint for idempotency within the quote window.
4. Calls the service-role-only `create_authoritative_quote` RPC with the expected booking-session version.
5. Atomically creates immutable vehicle, location, service-request, optional route, quote, and line-item records.
6. Returns the persisted pricing snapshot, not a browser calculation.

Quote revisions supersede prior active quotes without mutating their pricing snapshots. Stale draft versions are rejected, and an accepted session cannot be repriced. Quotes expire after 30 minutes and are regenerated by the client hook.

## Structure

- `services/pricingPolicy.js`: canonical page-3 pricing keys and server-authority policy.
- `services/pricingEngine.js`: pure itemized calculators for all seven service paths.
- `repositories/pricingParameterRepository.js`: effective version loading and completeness checks.
- `repositories/quoteRepository.js`: transactional quote creation, lifecycle RPCs, ownership checks, and persisted snapshot loading.
- `services/quoteService.js`: trusted booking-data orchestration, snapshots, expiry, and idempotency.
- `hooks/useAuthoritativeQuote.js`: loading, retry, and 30-minute refresh behavior.
- `hooks/useAcceptedQuote.js`: server-backed checkout gate for the exact accepted quote.
- `schemas/quoteSchema.js`: safe API response validation.

Replacement tires and gas delivery mileage beyond the included distance are marked `confirmation_required` and excluded from `totalPayableNowCents`.

## Lifecycle

The public API maps the database `offered` state to `active`. Session-authorized RPCs enforce `active → accepted`, `active → declined`, `active → superseded`, and time-based `active → expired` transitions. Every transition is recorded in `audit_logs`. S8A reloads the stored quote and remains blocked unless its status is `accepted`; browser-submitted totals are never accepted.
